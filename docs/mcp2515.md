# Raspberry Pi + MCP2515

Frogdash uses Linux SocketCAN. The MCP2515 kernel driver supplies `can0`; no Python
SPI library or separate decoder is required. The modules use **500 kbit/s,
classical 11-bit CAN**. The Pi model, board supply/logic design, crystal frequency
and transceiver still need confirmation before finalizing the electrical setup.

## Proposed wiring

For a standard Pi 40-pin header, SPI0 CE0, and interrupt GPIO25:

| Module signal | Pi BCM function | Physical pin |
| --- | --- | --- |
| SI / MOSI | GPIO10 / SPI0 MOSI | 19 |
| SO / MISO | GPIO9 / SPI0 MISO | 21 |
| SCK | GPIO11 / SPI0 SCLK | 23 |
| CS | GPIO8 / SPI0 CE0 | 24 |
| INT | GPIO25 | 22 |
| GND | Ground | 25 |
| VCC | **Board-specific; confirm first** | Not assigned |
| CANH / CANL | Vehicle CANH / CANL | Not Pi GPIO |

These pins must be free of other HAT/display assignments. Pi GPIO inputs are
**3.3 V tolerant**, not 5 V tolerant. Many MCP2515+TJA1050 boards run both chips
at 5 V without Pi-safe SPI/INT levels. Powering that entire board from 3.3 V is
not a general fix: TJA1050 requires 4.75–5.25 V. Use a board designed for 3.3 V
host logic or an appropriate supply/level interface. Sources:
[Pi GPIO voltage limits](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#voltage-specifications),
[TJA1050 datasheet](https://www.nxp.com/docs/en/data-sheet/TJA1050.pdf),
[MCP2515 datasheet](https://ww1.microchip.com/downloads/aemDocuments/documents/APID/ProductDocuments/DataSheets/MCP2515-Family-Data-Sheet-DS20001801K.pdf).

Use a shared signal ground and twisted CANH/CANL pair. Terminate the two physical
ends with 120 ohms, not every module. With power off, the two parallel resistors
read about 60 ohms between CANH/CANL. Use regulated power for the Pi/module,
not vehicle battery voltage directly.

## Driver and persistent bitrate

After confirming the crystal, generate the boot configuration. This example
is **only for an 8 MHz board**:

```sh
python3 tools/mcp2515_config.py --oscillator 8000000 --interrupt 25 --cs 0
```

Use `16000000` for 16 MHz or `20000000` for 20 MHz. The script prints the SPI
enable and overlay lines without changing boot files. Add them under an applicable
`[all]` section in `/boot/firmware/config.txt` (older OS: `/boot/config.txt`), remove
conflicting duplicate CAN overlays, and reboot. SPI speed is conservatively 1 MHz.
See the [official overlay reference](https://github.com/raspberrypi/linux/blob/rpi-6.12.y/arch/arm/boot/dts/overlays/README).
`mcp2515-can1` selects SPI CE1; it does not guarantee Linux interface name `can1`.

```sh
sudo apt install can-utils
ip link show can0
dmesg | grep -i -E 'mcp251|spi|can'
sudo cp hardware/systemd/frogdash-can.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now frogdash-can.service
ip -details -statistics link show can0
candump can0
```

The unit brings `can0` up at 500000 bit/s with 100 ms bus-off restart before the
dashboard starts. Use this unit **or** an existing CAN network-manager profile,
not competing managers. Its boot job is limited to ten seconds if the device is
missing. Keep `--interface can0` in Frogdash arguments. CAN reception, commands,
GPS broadcasts and logging then use this interface without protocol changes.

Check real frames and error/drop counters on the bench. Desktop tests cannot
verify wiring, crystal selection, electrical levels or bus loading.

## PiSugar UPS coexistence

The [PiSugar 3 Plus](pisugar-power.md) uses I2C1 on BCM2/3 (header pins 3/5),
addresses 0x57/0x68. It does not share the MCP2515 SPI signals or BCM25 IRQ.
The old BCM23/24 ACC/relay power wiring and service are retired during that
migration; keep CAN termination, oscillator and bitrate settings unchanged.
